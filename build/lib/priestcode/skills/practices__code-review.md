# Code review

## When to use
Reviewing or submitting a change.

## Checklist
- Review correctness and design first, style last (let a formatter handle style).
- Small PRs; explain the why; leave specific, kind, actionable comments.
- As author: self-review the diff first; keep PRs focused.

## Pitfalls
- Nitpicking style while missing a real bug.
- Huge PRs get rubber-stamped.
