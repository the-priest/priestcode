# Naming things

## When to use
Any time you name a variable, function, or type.

## Checklist
- Name by intent/role, not type or implementation; be consistent across the codebase.
- Length proportional to scope; avoid abbreviations and misleading names.
- Booleans read as predicates (is/has/can).

## Pitfalls
- Vague names (data, tmp, manager) hide meaning.
- A name that lies about what the thing does.
