# Writing documentation

## When to use
Documenting a project or API.

## Checklist
- Start with what it does and how to run it; then the gotchas.
- Show, don't just tell — runnable examples; keep docs next to code and current.
- Document the why for non-obvious decisions.

## Pitfalls
- Docs that drift from the code mislead worse than none.
- Auto-generated docs with no examples.
