# Test coverage

## When to use
Deciding what still needs testing.

## Checklist
- Measure branch coverage; look at what's uncovered and why.
- Prioritize risky/complex code over trivial getters.
- Coverage tells you what's untested, not that tested code is correct.

## Pitfalls
- Chasing 100% leads to worthless tests.
- High coverage with weak assertions is false comfort.
