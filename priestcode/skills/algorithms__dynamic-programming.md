# Dynamic programming

## When to use
Working on dynamic programming.

## Checklist
- Define the state and recurrence; identify overlapping subproblems and optimal substructure.
- Top-down (memo) or bottom-up (table); reduce space when possible.
- Verify on small cases by hand.

## Pitfalls
- Wrong state definition → subtle incorrectness.
- Forcing DP where greedy/simple works.
