# Design patterns

## When to use
Deciding on design patterns.

## Checklist
- Recognize the problem each pattern solves (strategy, factory, observer, adapter).
- Apply the simplest thing that works; a pattern is a means, not a goal.
- Name things after intent.

## Pitfalls
- Pattern-itis: forcing patterns onto simple problems.
- Singletons as global mutable state.
